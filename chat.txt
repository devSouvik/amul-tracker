Good news — I found the actual mechanism. The Amul shop site doesn't need a headless browser at all; the pincode modal and stock check are backed by a plain JSON REST API. That repo's Puppeteer approach works but is way heavier than necessary. Here's what's actually happening under the hood, and then I'll build you a CLI tool that talks to the API directly.

How shop.amul.com really works (reverse-engineered):

GET https://shop.amul.com/en/browse/protein → gives you session cookies.
GET https://shop.amul.com/user/info.js → gives a session/tid token.
GET https://shop.amul.com/entity/pincode?...&filters[0][value]=<pincode> → resolves your pincode to a "substore" (region) — this is literally what that popup dropdown is doing.
PUT https://shop.amul.com/entity/ms.settings/_/setPreferences with { data: { store: <substore alias> } } → "selects" that region, same as clicking the dropdown item.
GET https://shop.amul.com/api/1/entity/ms.products?...&substore=<substoreId> → returns product JSON including available, inventory_quantity, alias, price, etc.
So: no Puppeteer/Playwright needed. Just axios + a cookie jar (tough-cookie / axios-cookiejar-support). This will be far faster, lighter, and less flaky than driving a real browser.

Answering your last question directly: no, you don't need Puppeteer/Playwright.

The pincode modal and stock display are just a UI on top of an undocumented JSON API. I traced the exact requests (see the README for the full mapping) and built a CLI that hits them directly with axios + a cookie jar — no browser, no rendering, no waiting for selectors.

What it does:

Warms up a session (cookies) the same way the page load does.
Looks up your pincode → resolves it to Amul's "substore" region (this is the dropdown).
"Selects" that region via the same setPreferences call the click triggers.
Queries the product API filtered by your product's alias, for that region, and reads available / inventory_quantity.
Usage:

bash
npm install
node cli.js -u "https://shop.amul.com/en/product/amul-chocolate-whey-protein-34-g-or-pack-of-30-sachets" -p 302001 --watch --interval 90
No Telegram — just terminal output, plus a native desktop notification (via node-notifier) the moment it flips to in-stock.

Two honest caveats:

This API is unofficial/reverse-engineered, so it can break silently if Amul changes it — I documented how to re-diagnose that in the README.
I couldn't hit the live network from this sandbox to test it end-to-end, so I'd try a single non-watch run first (node cli.js -u ... -p ...) to confirm the endpoints still behave as captured before trusting --watch.
